## 开天劈地之前

1. 如何初始化寄存器？

大部份的内核开发教程都会在跳转到loader之前，或者进入保护模式之前，都有着统一的初始化ax寄存器逻辑，然后用ax寄存器的值设置各个段寄存器。
但是大多都没有说明为什么要这么做，也不说明为什么要设置为这个值或那个值，对于打破砂锅问到底的人来说这很恐怖😱。

下面是3种初始化ax的方法：
```asm
mov ax, cs
mov ax, 0
xor ax, ax
```

至于为什么会有3种，其实都是一个目标,**将ax的值置为0*。绝大多数实机BIOS、bochs、qemu都默认在通电开机时将cs:ip的值设置为0x0000:0x7c00，即`mov ax, cs`就是将ax的值设置为0。
所以最后统一一下就是，在通电开机后，应该是初始化所有段寄存器的值都统一为0，后续的开发就更简单，给出的值就是物理偏移，0+任何地址都是目标地址。

2. 远跳转后寄存器的值是什么样的？

关于`jmp 0x1000:0`，这条代码执行完后，得到的是cs=0x1000,ip=0x0000，达到进入另一个段执行代码的逻辑，在这之前可能一直都在cs为0x0000的段下运行代码。

3. 为什么一些内核开发教程进入loader.bin的逻辑不用远跳转？

普通的`jmp`指令只会修改`ip`指令指针寄存器的值，`cs`还是原来的代码段，但是`ip`寄存器是相对偏移，相对的是`cs`段基址寄存器的值，普通的`jmp`，如`jmp 0x9000`，得到的是`cs:ip=0x0000:0x9000`，后续执行`0x9000`之后的代码，但是这块地方可能什么都没有，也可能是其他不被期待的代码，因为真的`loader`可能是指定存放到内存的`0x90000`处，应该通过0x9000:0访问，而普通的`jmp 0x9000`跳不到目标地址。

另有一些内核开发教程在跳转到`loader`时没有使用远跳转，这是因为它们将`loader`存放在`0xffff`以下的地址，因为实模式下`ip`寄存器最大只能表示`0xffff`。

另：为什么设置为`0x8000`不用担心`loader`太大呢？
从0x8000~0xffff一共0x8000字节，也就是8*16^3=32768字节，一共64个扇区，绝大多数玩具操作系统都可能完全用不到64个扇区，所以完全不用担心。

4. 实模式下内存布局

```
0x00000 ~ 0x003FF   中断向量表（IVT）          ← 不要动
0x00400 ~ 0x004FF   BIOS 数据区               ← 不要动
0x00500 ~ 0x07BFF   可用（比较小）
0x07C00 ~ 0x07DFF   引导扇区本身              ← 通常保留
0x07E00 ~ 0x9FBFF   大片可用区域（推荐）
0x9FC00 ~ 0x9FFFF   EBDA（扩展BIOS数据区）    ← 尽量避开
0xA0000 ~ 0xBFFFF   显存                      ← 绝对不能放代码
0xC0000 ~ 0xFFFFF   ROM / BIOS                ← 不能写
```

5. org的必要性？

在汇编器的逻辑中，文件开头的第一行代码的地址就是0x0000，所有指令都有地址，且都是从0x0000开始，所以如果有个标签（函数名称、循环标记、退出标记等），它也有一个地址，如flag=0x0010，没有org，则jmp flag就是jmp 0x0010，导致cpu飞出去；
指定了org 0x8000，则汇编器会认为起始地址在0x8000，然后这个标签对应的地址就是0x8010，jmp flag就是jmp 0x8010，得到正确的地址；

总的来说，org 0x8000/section xxx vstart=0x8000，告知汇编器将标记的值从0x8000开始计算，得到一个地址，这个会写入目标文件，影响到绝对跳转指令的运行。

绝对跳转：jmp、call等
相对跳转：loop、jmp short label
